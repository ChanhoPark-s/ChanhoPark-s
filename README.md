- 여러 프로젝트에서 팀장 역할을 맡으며 기술뿐 아니라 **역할 분배, 일정, 우선순위, 협업의 흐름**도 함께 경험했습니다.

단순히 요청받은 기능을 구현하는 것보다  
**실제 업무가 어떻게 흘러가고, 각 시스템이 그 과정에서 어떤 역할을 하는지 이해하는 것**을 중요하게 생각합니다.

### What I Do

- Nexacro 기반 업무 화면 개발 및 개선
- Java / Spring 기반 비즈니스 로직 개발 및 유지보수
- Oracle / SQL 기반 데이터 조회 및 업무 로직 처리
- 입고·출고·재고 등 WMS 업무 프로세스 개발·운영
- 현업 요구사항 분석 및 시스템 반영
- 운영 이슈 분석 및 장애 대응
- GitLab 기반 소스 형상관리
- GitLab Runner / CI·CD 환경 활용
- 개발 및 배포 환경 개선
- 업무 흐름과 시스템 구성 문서화

### How I Work

업무시스템의 문제는 한 화면이나 한 코드에서 끝나지 않는 경우가 많았습니다.

그래서 저는

**현업 업무 → 화면 → 서버 로직 → 데이터 → 운영 환경**

까지 이어지는 흐름을 따라가며 문제를 이해하려 합니다.

처음 접하는 영역도 필요한 만큼 직접 익히고,  
반복되는 불편은 단순 대응으로 끝내기보다 **더 나은 개발·운영 방식으로 연결하는 것**을 중요하게 생각합니다.

# 🤝 Leadership

저는 리더의 역할을 모든 일을 직접 하는 것이 아니라,  
**구성원의 강점을 파악하고 역할과 우선순위를 조정해 팀 전체가 가장 잘 움직이도록 만드는 것**이라고 생각합니다.

개발 교육과정에서 여러 차례 팀장과 조장을 맡아

- 역할 분배
- 일정 및 진행 상황 조율
- 개발 우선순위 설정
- 구성원 간 의견 조정
- 결과물 검토
- 최종 발표

까지 프로젝트 전반을 경험했습니다.

대학에서도 학생회 운영기획부와 운영기획부장으로 활동하며  
행사 기획, 인력 배치, 일정 조율과 현장 운영을 경험했습니다.

이러한 경험을 바탕으로 개발 역량을 충분히 쌓은 뒤  
향후에는 **PL / Technical PM**으로 역할을 확장하고자 합니다.

# 🌱 How I Think

### 01. 과정을 익히며 전체를 읽습니다.

하나의 기능만 보는 것보다  
그 기능이 실제 업무와 시스템 전체에서 어떤 역할을 하는지 이해하려 합니다.

### 02. 필요한 기술은 직접 익힙니다.

특정 기술에만 머무르기보다  
문제를 해결하는 데 필요한 영역이라면 직접 배우고 연결합니다.

### 03. 생각을 실제 변화로 연결합니다.

더 나은 방법을 떠올리는 데 그치지 않고  
실제 개발과 운영 환경에서 사용할 수 있는 수준까지 구현하려 합니다.

### 04. 사람도 시스템의 일부라고 생각합니다.

프로젝트는 코드만으로 완성되지 않습니다.  
구성원의 강점과 역할, 일정과 우선순위가 맞물려야 더 좋은 결과를 만들 수 있다고 생각합니다.
